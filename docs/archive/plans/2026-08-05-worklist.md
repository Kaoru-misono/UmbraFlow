## 一、没落进任何文档的(这一节是新增内容)

### 1.1 模板全部是无掩膜裁的 —— 假阳性的真正根因

**27 个模板里 26 个没有颜色键**,即整块矩形像素直接比。这一天里的模板假阳性
(`seasonevent_crest` 烧掉四轮、`seasonflashpick_pill` 把战斗结算页的奖励条认成了
查看内容药丸)根因都在这里:**没有掩膜,比的就是"这块矩形长得像不像",背景一起进了分母。**

分母有多大是可以算的。`seasonevent_crest` 是 104×72 = 7488 个像素,判据是
`score * 10000 <= maximum * (10000 - threshold)`(`observe.matched`),score 是逐像素
绝对差之和。所以 threshold = 8500 基点的实际含义是**平均每像素差 38 灰阶以内即命中**
(255 的 15%)。而那块裁图里真正是纹章的只占一小部分,其余是黑底——于是"左上角偏暗"
这一个条件就够它命中,这正是它在 59 张屏上解析成功的机制。

当时的补救是调阈值(8000 → 9500),那只是把症状压下去。正确做法是重裁:
`scribe.measure` 的键**同时裁 crop 和 probe**,带键出来的 PNG 多一个 alpha 平面,
匹配时只比键选中的像素。流程是先不带键裁一块 → `explore.probe` 看色彩普查 → 挑键 → 带键重裁。

**做完算什么**:至少 `seasonflashpick_pill`、`seasonevent_crest`、`seasonroute_zoom`
三个带键重裁,并且**在各自曾经误命中的那张帧上证伪**(不是只验正例)。

> **2026-08-05:颜色键现在可以反着用。** 此前一把键只能说"留下靠近这个颜色的像素",
> 于是多彩的标记(纹章、徽记)根本没有可用的键——没有任何单色能选中它。新增
> `removes`:同一把键改说"去掉靠近这个颜色的像素"。多彩标记压在单色底上时,选中它的
> 办法就是点名那块底。写法是 appearance 段多一行 `key_removes = true`,不写等于 false,
> 所以此前所有文件逐字节不变。`scribe.measure` 的 key 表、`explore.crop` / `explore.probe`
> 都接同一个字段。**仍然只支持一种颜色**:反选是那一种颜色的补集,不是多色并集。

- 要真机:**是**(要回到那些页面上重裁)
